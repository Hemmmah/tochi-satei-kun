# 1. レビューの目的

このレビューの目的は、企画そのものを再構築することではありません。

目的は次の4点です。

1. 既存リポジトリの状態で企画を実装できるか確認する  
2. 講座制作中に発生しそうな技術的・仕様上の事故を事前に見つける  
3. 8月22日までの公開・提示を妨げるブロッカーを特定する  
4. 企画の前提を維持したまま、最小変更で実行可能性を高める  

---

# 2. 固定前提

以下は意思決定済みです。通常のレビューでは変更提案をしないでください。

1. 第1弾は約60分のUdemy講座とする  
2. 「不動産鑑定士が教えるシリーズ」の名称を使う  
3. 主題は土地査定AIエージェントである  
4. Python未経験の不動産実務者を対象にする  
5. 受講者はコードを手入力しない  
6. バイブコーディング形式とする  
7. 既存の土地査定クンを査定エンジンの正本とする  
8. OpenAI側とClaude側で査定ロジックを二重実装しない  
9. 共通Agent仕様と薄いアダプターへ分離する  
10. OpenAI側の主環境はCodex、Anthropic側はClaude Codeとする  
11. カスタムGPTを主環境にしない  
12. Workspace Agentsや独自MCPを受講必須にしない  
13. LLMに査定価格を計算・推測・補完させない  
14. 媒介査定・一次スクリーニング支援として扱う  
15. 鑑定評価とは明確に区別する  
16. 最終判断と説明責任は人間に残す  
17. AutoMLは本編必須にしない  
18. 2026年8月22日までに提示可能なポートフォリオを作る  
19. 2026年8月のプレスリリース案件にする  
20. 企画の目的はUdemy売上だけでなく、信用資産・OSS・法人研修への転用である

# 4. 前提変更を許可する例外

次の場合だけ、固定前提への変更を提案できます。

- 現行コード上、技術的に実現不可能
- 再現可能な重大バグがある
- データ利用・セキュリティ・法令上の明確な問題がある
- 受講者がほぼ確実に完走できない
- 8月22日までの公開を不可能にする致命的な工数が必要
- OpenAIまたはClaudeの実環境で、想定する配布・実行方法が使用不能

その場合も企画全体を書き直さず、次の形式で一件ずつ報告してください。

```text
[前提レベルの例外]
対象前提：
問題：
証拠：
影響：
最小の代替策：
代替後も維持できる企画要素：
```

抽象的な懸念だけで前提変更を提案しないでください。

# 6. レビュー観点

以下の順に確認してください。

## A. Blocker

制作着手前に解決しなければ、講座が成立しない問題。

例：

- OpenAI側で想定形式を導入・実行できない
- Claude側のSkillが現行コードと不整合
- 査定価格が環境ごとに変わる
- 教材データを合法・安全に固定できない
- 60分講座の成果物が生成できない
- 初心者が復旧不能な環境依存

## B. Major

公開はできるが、返金・低評価・誤解・保守不能につながる問題。

例：

- READMEとコードの仕様差
- 受講手順の抜け
- Windows特有の失敗
- Excelと説明上の数値の不一致
- 講座表現と実際の対応範囲の差
- 警告や免責が出力に残らない
- 片方のアダプターだけ仕様が分岐する

## C. Minor

公開前後に修正可能な改善。

例：

- ファイル名
- 文言
- 章順
- READMEの分かりやすさ
- トラブルシューティングの補足

# 8. 出力形式

以下の形式で回答してください。

## 1. 結論

次のいずれかを一つ選ぶ。

- `GO`
- `GO WITH CONDITIONS`
- `NO-GO`

2〜5行で理由を書く。

## 2. Blocker

各項目について次を記載する。

```text
ID：
問題：
証拠（ファイル／関数／テスト／行）：
講座への影響：
最小修正：
修正工数の概算：
Gate 0での確認方法：
```

該当なしの場合は「なし」と明記する。

## 3. Major

Blockerと同じ形式。

## 4. Minor

簡潔な一覧。

## 5. 企画書と現行実装の不一致

表形式で記載する。

| 企画書の記述 | 現行実装 | 判定 | 最小修正 |
|---|---|---|---|

## 6. 必要な追加成果物

次の分類で記載する。

- 必須
- あると良い
- 今回は不要

## 7. Gate 0実行チェックリスト

実際にコマンドまたはテストで確認できる形にする。

## 8. 8月22日までの最小実装順

最大10ステップ。優先順位順。

## 9. 工数評価

企画書の45時間上限について、

- 現実的
- 条件付きで現実的
- 非現実的

のいずれかを選び、超過要因と削減案を示す。

## 10. 最終提案

企画の根幹は維持し、今すぐ着手する最初の3タスクだけを示す。
